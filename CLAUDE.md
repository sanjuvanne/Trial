## Development Workflow

### Branching

- Feature branches should be created from the main branch
- Use descriptive branch names

### Commits

- Write clear, concise commit messages
- Focus on *why* a change was made, not just *what* changed

### Code Quality

- Review code for security vulnerabilities (OWASP top 10) before committing
- Keep changes minimal and focused — avoid unrelated modifications in the same commit

## Conventions

- Prefer simplicity over abstraction
- Only add error handling at system boundaries (user input, external APIs)
- Do not add comments, docstrings, or type annotations to code you did not change
- Remove unused code entirely rather than commenting it out
